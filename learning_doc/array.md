# Go 源码学习笔记：数组 (Array)

在 Go 语言中，数组是一种长度固定的、由同类型元素组成的数据结构。与灵活的切片（Slice）相比，数组在 Go 中扮演着更基础但同样重要的角色。切片的底层实现正是基于数组。

## 1. 数组的运行时表示

在 Go 的运行时中，关于数组类型的元信息由 `src/internal/abi/type.go` 文件中的 `ArrayType` 结构体定义。

```go
// ArrayType represents a fixed array type.
type ArrayType struct {
	Type
	Elem  *Type // array element type
	Slice *Type // slice type
	Len   uintptr
}
```

这个结构体描述了一个数组类型的核心属性：

*   **Type**: 这是一个嵌入的结构体 (`abi.Type`)，包含了所有 Go 类型共有的信息，如类型的大小（`Size_`）、对齐方式（`Align_`）、种类（`Kind_`，对于数组来说是 `abi.Array`）等。
*   **Elem**: 一个指向 `abi.Type` 的指针，描述了数组中存储的**元素的类型**。例如，对于数组 `[5]int`，`Elem` 就指向代表 `int` 类型的 `abi.Type`。
*   **Slice**: 一个指向 `abi.Type` 的指针，描述了与此数组类型**相对应的切片类型**。例如，对于数组类型 `[5]int`，`Slice` 就指向 `[]int` 类型。这体现了数组和切片之间的紧密联系。
*   **Len**: 数组的**固定长度**。这是一个 `uintptr` 类型的值，在编译时就已经确定。

**关键点**：`ArrayType` 描述的是**数组的类型**，而不是数组实例本身。一个数组实例在内存中就是一块连续的、包含了其实际元素的内存空间。`ArrayType` 提供了让运行时理解这块内存布局所需的所有元信息。

## 2. 数组是值类型

这是 Go 中数组最重要的特性之一。与 C/C++ 不同，当一个数组变量被赋值给另一个变量，或者作为参数传递给一个函数时，Go 会**完整地复制**整个数组。

```go
func main() {
    arr1 := [3]int{1, 2, 3}
    arr2 := arr1 // arr1 的所有元素被复制到 arr2

    arr2[0] = 99

    fmt.Println("arr1:", arr1) // 输出: arr1: [1 2 3]
    fmt.Println("arr2:", arr2) // 输出: arr2: [99 2 3]
}
```

**为什么会这样？**

因为数组变量直接代表了整个数据结构。`arr1` 和 `arr2` 在内存中是两个完全独立的实例。这种行为与切片、map、channel 等引用类型形成鲜明对比。

**优点**:
*   **数据隔离**: 保证了数据的安全，函数接收数组副本，可以随意修改而不用担心影响到调用者。
*   **可预测性**: 行为简单明了，没有隐藏的引用关系。

**缺点**:
*   **性能开销**: 当数组很大时，复制整个数组会带来显著的性能开销。因此，在 Go 中很少直接传递大型数组，更常见的做法是传递指向数组的指针或使用切片。

## 3. 数组与切片的区别

| 特性 | 数组 (Array) | 切片 (Slice) |
| :--- | :--- | :--- |
| **类型定义** | `[N]T` (长度 `N` 是类型的一部分) | `[]T` (长度不是类型的一部分) |
| **长度** | 固定，在编译时确定 | 动态，可以改变 |
| **值类型** | **值类型** (复制传递) | **引用类型** (传递的是切片头的副本，共享底层数组) |
| **内存** | 变量直接持有所有元素 | 变量是一个“切片头”，指向底层数组 |
| **零值** | 是一个可用的、元素为零值的数组 | `nil` (指针为 `nil`, len=0, cap=0) |
| **主要用途** | 作为切片的底层数据结构；用于需要精确内存布局的场景 | 作为动态数组，是 Go 中最常用的集合类型 |

**示例**:
`[5]int` 和 `[10]int` 是两种**完全不同**的类型。你不能将一个 `[5]int` 类型的变量赋值给一个 `[10]int` 类型的变量。

```go
var a [5]int
var b [10]int
// a = b // 编译错误: cannot use b (variable of type [10]int) as [5]int value in assignment
```

## 常见面试题

### 1. 数组和切片有什么区别？

**回答**:
这是最经典的问题。需要从几个维度回答：
1.  **长度**: 数组长度固定，是其类型的一部分。切片长度可变。
2.  **类型**: `[5]int` 和 `[10]int` 是不同类型。所有 `[]int` 都是相同类型。
3.  **传递方式**: 数组是值类型，函数传递会复制整个数组。切片是引用类型（的轻量结构），函数传递的是切片头的副本，但它们指向同一个底层数组，因此函数内部对元素的修改会影响外部。
4.  **内存布局**: 数组变量代表整个数据块。切片变量是一个包含指针、长度和容量的结构体。

### 2. 什么时候应该使用数组而不是切片？

**回答**:
虽然切片更常用，但在某些特定场景下数组是更好的选择：
1.  **固定大小且数量已知**: 当你明确知道集合需要容纳多少个元素，并且这个数量不会改变时，例如表示一周七天、一个颜色的 RGBA 值等。
2.  **性能和内存布局要求高**: 当你需要精确控制数据在内存中的布局时，例如在进行系统编程、与 C 库交互或优化性能时。因为数组是一块连续的内存，没有额外的头部开销。
3.  **作为其他数据结构的基础**: 数组是构建切片、map 等更复杂数据结构的基础。

### 3. Go 中的数组是值类型还是引用类型？这带来了什么影响？

**回答**:
数组是**值类型**。
*   **影响**:
    *   **赋值和传参是全量复制**: `arr2 = arr1` 会创建一个 `arr1` 的完整副本。将数组传递给函数也会复制整个数组。
    *   **性能考量**: 对于大数组，复制开销很大。为了避免这种情况，可以传递**指向数组的指针** (`*[N]T`)，这样就只会复制一个指针的开销。
    *   **数据安全**: 由于是值传递，函数内部对数组副本的修改不会影响到原始数组，保证了数据的隔离性。

### 4. 如何在函数间共享一个数组而避免复制开销？

**回答**:
有两种主要方法：
1.  **传递数组的指针**: 函数签名改为接收 `*[N]T`。这样只会复制一个指针的成本，函数内部通过解引用指针来修改原始数组。
    ```go
    func modify(arr *[3]int) {
        (*arr)[0] = 100
    }
    
    func main() {
        a := [3]int{1, 2, 3}
        modify(&a)
        fmt.Println(a) // 输出: [100 2 3]
    }
    ```
2.  **使用切片**: 这是更 idiomatic (地道) 的 Go 做法。创建一个指向数组的切片，然后将切片传递给函数。
    ```go
    func modify(slice []int) {
        slice[0] = 100
    }

    func main() {
        a := [3]int{1, 2, 3}
        modify(a[:]) // 从数组创建切片
        fmt.Println(a) // 输出: [100 2 3]
    }
    ```
    在绝大多数情况下，使用切片是更灵活和推荐的方式。
